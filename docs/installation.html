Installation


Download the installer, run it, and the new right-click menu is on. This page also covers the portable version, updates, and how to remove Nilesoft Shell Pro.

Warning: If the original Nilesoft Shell is installed, uninstall it first. Nilesoft Shell Pro has its own name, so it does not replace the original (installed with its own installer, winget, Scoop or Chocolatey, or extracted as a portable copy). Both would stay registered with Explorer and collide: the context menu can stop appearing or show up twice. Open Settings → Apps → Installed apps, choose Nilesoft Shell and Uninstall; for a portable copy, run shell -unregister -restart from its folder and delete the folder. Back up your shell.nss and imports folder first if you want to keep your configuration. Updating from an earlier Nilesoft Shell Pro version is fine.
Warning: Nilesoft Shell Pro is not code-signed, so newer Windows versions may block it. If the installer or the app will not open, or the right-click menu does not change after installing, do these steps:
  1. Unblock the download. Right-click the downloaded .msi or .zip, choose Properties, tick Unblock at the bottom and press OK. For the portable zip, do this before you extract it.
  2. "Windows protected your PC" (SmartScreen). Click More info, then Run anyway.
  3. Smart App Control. If Windows says it blocked the app to protect you, Smart App Control is on. It has no way to allow a single app, so you have to turn it off: open Windows Security → App & browser control → Smart App Control settings and choose Off. Then run the installer again.
  4. Microsoft Defender. If Defender removed or blocked a Shell file (for example shell.dll, shell.exe, NilesoftShellPro.exe or the installer):
    1. Open Windows Security → Virus & threat protection → Protection history. Find the entry for the Shell file, then choose Actions → Restore (or Allow on device).
    2. So it does not happen again, add an exclusion: in Virus & threat protection, under Virus & threat protection settings, choose Manage settings. Scroll to Exclusions, choose Add or remove exclusions → Add an exclusion → Folder and pick C:\Program Files\Nilesoft Shell (or the folder you extracted the portable version to).
    3. Run the installer again if a file was missing, or restart Explorer.
  5. Another antivirus. Restore the Shell file from its quarantine and add the same folder, C:\Program Files\Nilesoft Shell (or your portable folder), to its exclusions (allowed list). Then restart Explorer or sign out and back in.
Only download Nilesoft Shell Pro from the official releases page. You can check a file against SHA256SUMS.txt from the same release.

Installer version
Install

Download setup-x64.msi (or the ARM64/x86 one), run it and approve the administrator prompt. It installs to C:\Program Files\Nilesoft Shell\, registers Shell for all users with the Windows 11 classic menu, restarts File Explorer and adds Nilesoft Shell Pro to the Start menu.

Installing a newer version of Nilesoft Shell Pro over an older one upgrades it in place and keeps your shell.nss. The original Nilesoft Shell must be uninstalled first (see the warning at the top). Your personal configuration is brought up to date the next time you open the app; see Updates and your configuration.

Uninstall

Open Settings → Apps → Installed apps, find Nilesoft Shell Pro and choose Uninstall. Shell is unregistered and File Explorer restarts. Your per-user configuration in %APPDATA%\Nilesoft\Shell is left in place.


How updates work

The Nilesoft Shell Pro app updates itself from this project's GitHub releases (see Preferences: Updates). Updates don't ask for administrator rights:

  • Installed for all users (MSI): most releases only change the app and the menu files that come with it. Those are installed for you alone, in %LOCALAPPDATA%\Programs\Nilesoft Shell Pro\app\<version>, without touching C:\Program Files\Nilesoft Shell\. The Start menu shortcut and the app's autostart keep pointing to the installed app, which starts your newer copy for you. Other people on the PC keep the version they have until they update it themselves.
  • Shell core updates: when a release changes shell.dll or shell.exe, which an all-users install shares with everyone on the PC, the app says so and offers Install with administrator approval. Only then does Windows ask for approval, and only after you press that button. Automatic updates never do this; they only tell you about it.
  • Portable copy: the files in its folder are replaced, core included. The folder is yours, so no administrator rights are needed. This is also how a copy registered for you only (shell -register -user) gets core updates: its shell.dll lives in a folder you own, so the whole copy, core included, updates without administrator rights.

Every download is checked against the release's SHA256SUMS.txt before anything is installed, and an app update also against the SHA-256 of each of its files in the release's update.json. You can always install a release by hand instead: run the newer MSI, or replace the portable files. A newer MSI makes the app copies in %LOCALAPPDATA% unnecessary; they are removed the next time the app starts.


Updates and your configuration

Your personal configuration in %APPDATA%\Nilesoft\Shell holds copies of the menu files that come with Shell (shell.nss and the files in imports, such as modify.nss and theme.nss). An update only replaces the program folder, so in older versions those copies stayed as they were and never got the fixes of later versions.

Now the next start of the Nilesoft Shell Pro app after an update (from the installer, the portable zip or the app itself) brings them up to date:

  • A file you never edited is replaced with the one from the new version.
  • A file you edited is left as it is. Home lists it, and you can compare it with the new version or switch to the new version.
  • A file that is missing is added when your configuration imports it.
  • The files the app writes for you (imports\settings-app*.nss) and files of your own are never touched.

Before anything is replaced, all your files are saved as a snapshot on the Backups page, so you can compare or go back. Nothing of this runs as administrator, and the installer itself never touches your personal files. After an app update for an all-users install, the new menu files come from the app's own copy in %LOCALAPPDATA%, so a personal configuration gets them without administrator rights too. A configuration that is still the shared one in Program Files gets them with the next Shell core update. Without the app, run shell -config:upgrade (or shell -config:init, which does the same for files that already exist).


Portable version
Install

Download NilesoftShellPro-x64-portable.zip and extract it to a folder you own, for example %LOCALAPPDATA%\Programs\NilesoftShellPro. Run NilesoftShellPro.exe: its first-run setup creates your configuration and registers Shell for your account, with no administrator rights. Or run these yourself from that folder:

Command Prompt
shell -config:init
shell -register -user -treat -restart

To register for all users instead, run shell -register -treat -restart from an elevated command prompt.

Tip: To use Shell for your account only, without administrator rights, register an extracted (portable) copy with shell -register -user -restart and create your own configuration in %APPDATA%\Nilesoft\Shell with shell -config:init. See Command line.

For further details, see the chapter Command-Line Help below.

Uninstall

From the folder you extracted the program to, run (no administrator rights needed for a per-user registration; use an elevated prompt and leave out -user if you registered it for all users):

Command Prompt
shell -unregister -user -restart

Then delete the folder.


Tip: Close all instances of Windows File Explorer before uninstalling to avoid needing a reboot after it (Shell) has been uninstalled.

For further details see the chapter Command-Line Help below.


Command-Line Help

shell -[options]

Options
-register (-r) Registering.
-unregister (-u) Unregistering.
-user With -register or -unregister: register for the current user only (HKCU\Software\Classes). Needs no administrator rights. The icon overlay is machine-wide only and is skipped. With -treat on Windows 11 the redirect is written under HKCU\Software\Classes\CLSID\{86ca1aa0-34aa-4e8b-a509-50c905bae2a2}. If Shell is also registered for all users, the per-user registration takes precedence for that user.
-restart Restart Windows Explorer for the current session. Needs no administrator rights; other users' Explorer processes are not touched.
-treat Disable Windows 11 context menu.
-silent (-s) Prevents displaying messages.
-config:init [-force] Copy shell.nss and the imports folder from the install folder to %APPDATA%\Nilesoft\Shell. Existing files are kept unless -force is given; the ones you never edited are first brought up to date as with -config:upgrade. Needs no administrator rights.
-config:upgrade [-take:<file>] Bring the menu files in your personal configuration up to date with the install folder: replace the ones you never edited, add missing ones your configuration imports, and leave the ones you edited. A snapshot of your files is saved first (see Updates and your configuration). -take:imports/modify.nss also replaces that file if you edited it. Prints the result as JSON. Needs no administrator rights.
-config:reset Copy everything in %APPDATA%\Nilesoft\Shell to a backup-<timestamp> folder inside it, then copy the default shell.nss and imports again, overwriting. Other files are left in place. Nothing is overwritten if the backup fails.
-config:path Print the full path of the configuration file in use.
-config:check <file> Parse <file> and its imports (resolved relative to the importing file) with the same parser Explorer uses, without affecting the running menu, and print {"ok":bool,"root":"...","errors":[...],"warnings":[...]}, each entry {"file","line","column","message"}. Errors stop the configuration from loading; warnings (such as a missing import) do not. Exit code 0 if it loads, 1 if not, 2 if no file is given. Needs no administrator rights.
-config:tree <file> -context:<where> [-sample:<path>] Print the right-click menu for one place (file, folder, drive, thispc, back, desktop or taskbar) as JSON: your items and the items Windows and other programs add. Read-only; it never shows a window. See Command line.
-status Print a JSON object describing the installation: version, registration mode (none, user, machine or both) and the DLL each registration points at, the Windows 11 menu redirect state, the configuration file in use and where it was found (registry, appdata or install), and the per-user configuration folder. Only reads; needs no administrator rights. Exit code 0 (1 if the output could not be written).
-out:<file> Write the output of the -config:* and -status commands to a file (UTF-8) instead of standard output. Without it, output goes to standard output when that is a pipe or a file, otherwise to the console the command was started from.
-? Display this help message.
Keys to turn Shell on and off

These keys are used when you press right-click or press Shift+F10 keys

CTRL To enable and reload the configuration file shell.nss
WIN To make priority to the modern context menu for Windows 11
CTRL+WIN To turn Shell off in File Explorer until Explorer restarts
RIGHT-CLICK+LEFT-CLICK To reload the configuration file shell.nss

The right-click made with CTRL+WIN shows the plain Windows classic menu. After that, File Explorer shows the Windows menus: the Windows 11 menu on Windows 11, the classic menu on Windows 10. On Windows 10, right-click with CTRL held to turn Shell back on. On Windows 11 that does not work, because the Windows 11 menu never reaches Shell while it is off. Restart File Explorer instead, for example with shell -restart, or sign out and back in.
