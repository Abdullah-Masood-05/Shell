The app


Nilesoft Shell Pro (NilesoftShellPro.exe, next to shell.exe in the program folder) is a desktop app for checking an installation and editing the configuration without opening shell.nss by hand. It is part of this fork and is included in the MSI and the portable zip. The MSI adds it to the Start menu as Nilesoft Shell Pro, and running shell.exe without options opens it too.

Info: The app runs as the current user and needs no administrator rights. It works on the per-user configuration in %APPDATA%\Nilesoft\Shell and the per-user registration under HKEY_CURRENT_USER. The only action that asks for administrator rights is machine-wide registration in Preferences, which is marked with the UAC shield.
First run

On first start the app offers three steps:

  1. create the per-user configuration (shell -config:init);
  2. register Shell for the current user (shell -register -user);
  3. restart Explorer.
Home
  • Health: whether Shell is registered (none, user, machine or both), the state of the Windows 11 classic-menu redirect, the DLL in use and the version.
  • Active configuration: which shell.nss Explorer loads and where it was found, with an action to switch to a per-user copy.
  • Diagnostics: recent errors from shell.log. Each one opens the file at that line in the Config Editor.
  • Quick actions: register or unregister for the current user, restart Explorer, open the configuration folder, and run first-time setup again.

The app reads all of this through shell -status, so it shows the same state the command line reports.

Appearance

Theme, dark mode, density, background colour, opacity and effect, font, corner radius, border and shadow, with a live preview of the menu on your wallpaper in light and dark, for the desktop or File Explorer. Each value shows which file and line set it; values written as expressions are shown read-only with a link to the Config Editor.

At the top, Themes has the example themes of the original Nilesoft Shell project as cards, each a small menu drawn in that theme over your wallpaper. Click a card (or Apply in its … menu) to stage its theme keys as pending changes: the preview updates at once, and Save, Discard and Ctrl+S work as for any other change. A theme replaces the theme settings changed in the app, so if you have some, the app asks first; your own files are not touched. The card in use is marked Active. Export to clipboard copies a theme's theme{} block with its credit, and Export current look copies the theme settings in effect, ready to paste into a .nss file.

Behavior
  • Whether Shell's menu replaces the Windows 11 menu, and the submenu delay. The shipped configuration opens submenus after 200 ms; this replaces your Windows setting while a Shell menu is open, and you can turn it off here.
  • Tooltips: on or off, delay, width and colours.
  • Screenshots: on or off and the folder they are saved to.
  • Windows' own items: remove duplicates, disabled items and extra separators; show icons on them.
Rules & Filters

Where the menu is shown: only in File Explorer and on the desktop, programs and window classes to leave alone, or a raw exclude condition, which is checked when you save.

How changes are saved

Appearance, Behavior and Rules & Filters collect your changes until you press Save (or Ctrl+S). Only the keys you change are written, to an app-owned imports\settings-app.nss imported last by shell.nss, so your own theme and settings stay as you wrote them. Before writing, the new configuration is checked with shell -config:check; a configuration Shell would reject is not written. Each save takes a snapshot first (see Backups).

Context Menus
  • Modules: turn the bundled menus imported by shell.nss (terminal, file manage, develop, go to, taskbar, my tools) on or off. The line is commented out, not deleted.
  • System items: the modify and remove rules that hide, move or rename Windows' own items, in plain words, each with an on/off switch.
Menu Builder

Build your own menus, items and separators without writing NSS: title, icon (from Shell's icon font), command and arguments, where the item appears, and options such as running as administrator. The result is written to imports\settings-app-menus.nss, shown as code next to the tree, and read back when you open the page again.

Open with

Adds "Open with" items for your editors and terminals, so a file or folder opens in Zed, Cursor or PyCharm as easily as in VS Code. The page lists the apps it knows and looks for each one on this PC (read-only: the usual install folders, JetBrains Toolbox scripts and PATH):

  • VS Code, VS Code Insiders, Zed, Cursor, Windsurf, Sublime Text, Notepad++, IntelliJ IDEA, PyCharm, WebStorm, Rider, CLion, Visual Studio, Neovim (in a Windows Terminal tab), Windows Terminal, PowerShell 7, Git Bash and Notepad.
  • An app that wasn't found is greyed out with Locate… to point at its program yourself.
  • Add app adds any other program: a name, the program, an icon (its own by default), arguments, and whether it shows for everything, files only, folders only, or files with some extensions. Apps can be reordered, switched off, or set to run as administrator.
  • Arguments use placeholders: {path} the selected item, quoted (@sel.path.quote); {paths} every selected item (@sel(true)); {dir} its folder, or the folder itself ("@sel.dir"); {name} its name. Test shows the exact command line for a sample file and folder. It never starts the program.
  • The items go in a submenu (titled Open in by default, so it isn't confused with Windows' own Open with) or at the top level as Open with <name>, on files, folders, the folder background and the desktop as you choose. A preview shows the resulting menu.
  • Each item has the program's icon and a where path.exists(...) condition, so it disappears when the program is uninstalled.

The first time, the editors found on this PC are switched on; terminals and Notepad are off, because the Terminal and Develop menus have them already. The Develop menu's own Editors submenu (VS Code and Notepad) is left as it is by default: it only shows while Shift is held, so it doesn't crowd the everyday menu. If you'd rather have one place, the page can hide it (the lines in develop.nss are commented out, not deleted).

Saving writes imports\settings-app-openwith.nss (generated; edit it on this page rather than by hand) and imports it at the end of shell.nss once. As on the other pages, it is checked with shell -config:check first, a snapshot named Open with: … is taken, and Ctrl+S saves.

Config Editor
  • A tree of shell.nss and every file it imports. Imports that cannot be found are marked.
  • A highlighted read view with line numbers and problem markers, and an edit view.
  • While you type, the edit is checked with shell -config:check on a temporary copy, so the menu you are using is not affected. Problems link to their line.
  • Saving keeps the file's encoding, byte order mark and line endings. A file with errors is not saved unless you confirm, because one parse error turns the whole Shell menu off.
  • Files changed on disk by another editor are reloaded, or flagged if you have unsaved edits.
  • The shared configuration in the program folder is read-only here; the editor offers to create a per-user copy.
Backups

Every save first takes a snapshot of the configuration in %APPDATA%\Nilesoft\Shell\backups. The Backups page lists them with the time, the reason and the files changed. You can:

  • compare a snapshot with the current files, line by line;
  • restore a snapshot;
  • pin a snapshot so it is never removed when old snapshots are cleaned up;
  • create a snapshot by hand, delete one, or open the folder.
Preferences

The app's own theme, registration for all users (needs administrator rights), and version and licence information.

Applying changes

There is no restart step for configuration changes: Shell reloads the configuration when a file it loaded changes. Registration changes still need Explorer to restart, which the app does for the current session only.
