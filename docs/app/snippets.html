Snippets


A snippet is a small, ready-made addition to the right-click menu, such as Copy hash on a file or Compress to ZIP. The Snippets page lists the ones that come with the app and a selection from RubicBG's snippet collection. Turn one on and it is in the menu the next time you right-click. Turn it off and it is gone. You don't need to write or edit any code.

Finding a snippet
  • Type in Search snippets to filter the list by name or description.
  • Pick a category (for example Files, Archives, Windows or Apps) to see only those, or All to see everything.
  • The count at the top right says how many snippets are on.
What each row shows
  • The name and one line about what it does.
  • by ...: who wrote it. The snippets by Nilesoft Shell Pro are written for this app, use the MIT license and are built into it. by RubicBG is a link to RubicBG's collection on GitHub, where those snippets come from (see below).
  • Labels after the name, when they apply:
    • Runs as administrator: the snippet starts something with administrator rights. Windows asks you to allow it each time.
    • Uses the internet: the snippet opens a web page or sends something over the internet. The row's description says what is sent.
    • Needs ..., for example Needs 7-Zip: a program the snippet uses is not installed. The switch is greyed out until you install it. Come back to the page afterwards and the label is gone.
  • Show code opens the snippet's code under the row, so you can see exactly what it adds. Hide code closes it again. For a snippet by RubicBG the code is downloaded first, so this needs an internet connection.
Turning a snippet on or off

Click the switch. The change is saved right away; there is no Save button on this page.

  1. The app takes a snapshot of your configuration first.
  2. It checks the change with Shell. If Shell would not load the result, nothing is saved and a message says why.
  3. Shell picks up the change the next time you right-click.

A snippet that is on stays on after an update of the app. To undo a change, turn the switch back, or restore the snapshot on the Backups page.

Where the files go

When you turn on a snippet, the app copies it to imports\snippets\<name>.nss in your configuration folder (%APPDATA%\Nilesoft\Shell) and lists it in imports\settings-app-snippets.nss, a file the app looks after. shell.nss gets one line that loads that list:

import 'imports/settings-app-snippets.nss'

Turning a snippet off removes it from the list and deletes its copy. The snapshot taken before still has it.

On the Context Menus page the list shows up as the Snippets module. Turning that module off turns every snippet off at once, without changing the switches here; turning a snippet on turns the module back on.

Updates and your own changes

When a new version of the app brings a newer version of a snippet you have on, the app replaces your copy the next time it starts, as long as you never changed that copy.

If you edited the copy, for example in the Config Editor, your version is kept and the row says You changed this copy, so newer versions aren't applied to it. To get the bundled version back, turn the snippet off and on again.

Snippets by RubicBG

The rows by RubicBG come from RubicBG's Nilesoft Shell Snippets, a large community collection on GitHub. All credit for them goes to RubicBG. The page lists a selection: snippets that load in this version of Shell and don't need administrator rights, upload files, or change security settings. The names and descriptions on the page are written for this app.

  • Nothing of the collection is built into the app. A snippet is downloaded only when you turn it on (or press Show code), from a copy of the collection on GitHub at one fixed version.
  • The app knows the exact contents of every file it may download. If the download is different in any way, it is not used and nothing is changed.
  • Without an internet connection, turning one on shows Couldn't download the snippet and nothing is changed. Snippets that are already on keep working offline, because the copy in your configuration folder is what Shell loads.

The rest of the collection, and how to add any of its snippets by hand, is described on the Snippets page of these docs.

Troubleshooting
  • The switches are greyed out and a blue message is at the top. Explorer reads the shared configuration in the program folder, which the app never writes to. Press Create personal config.
  • Not saved: the config would fail to load. Shell rejected the result, so nothing was changed. The message names the file and line. Often it is another file in your configuration that already has an error: fix it in the Config Editor and try again.
  • A snippet is on but its item doesn't show. Most snippets only appear for some selections, for example Extract to folder only on a .zip file and New .gitignore only on the empty space in a folder. Also check that the Snippets module is on in Context Menus.
  • The copy in imports\snippets is missing. The file was deleted outside the app. Turn the snippet off and on again.
  • Couldn't download the snippet. Only snippets by RubicBG are downloaded. Check the internet connection and try again; nothing was changed in the meantime.
