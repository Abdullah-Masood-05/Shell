Preferences & Updates


Preferences is about the app itself: how it looks, whether it stays in the system tray and starts with Windows, registering Shell for everyone on this PC, keeping the app up to date, and version and licence information.

App theme

Choose System, Light or Dark. System follows the Windows app mode (Settings → Personalization → Colors) and changes with it while the app is open. This only changes the app's own window; the look of Shell's menu is set on Appearance.

Language

The app is available in English, Simplified Chinese (简体中文) and Traditional Chinese (繁體中文). Choose Auto, English, 简体中文 or 繁體中文. The change applies right away, with no restart.

  • Auto (the default) follows the Windows display language (Settings → Time & language → Language & region). Chinese for Taiwan, Hong Kong or Macao, or any Traditional Chinese, picks 繁體中文; any other Chinese picks 简体中文; every other language picks English. The card says which language Auto uses right now.
  • The setting only changes the app's own window. The text of Shell's menus comes from your configuration; the default configuration has its own language files in imports\lang.
  • Config keywords, file names and code samples stay in English in every language, because that is how you type them in shell.nss.
  • A language that is still being translated (Spanish, for now) is not in the list until at least half of the app is translated, and Auto doesn't pick it before then. Its translators can still see it with Test a translation file.

The choice is stored as Language under HKEY_CURRENT_USER\Software\Nilesoft\Shell\Settings (empty for Auto, en, zh-CN or zh-TW).

Translating the app

Anyone can translate the app; you don't need to be a programmer. All the text of the app is in one file per language, a gettext .po file: each English text, and under it a line for your translation. You can test your file in the app while you work on it, without building anything.

  1. Get the file. If your language already has a folder in src/settings/translations (for example es for Spanish), download the nilesoft-shell-pro.po inside it. If not, download the template, nilesoft-shell-pro.pot, and save a copy named after your language, for example fr.po. (On GitHub, use the Download raw file button.)
  2. Translate it. Poedit (free) is the easiest: open the file, click an English text and type yours below it. For a .pot, use Create new translation and pick your language, which also fills in the plural rules. Notepad++ or any text editor works too: fill in each msgstr "" line under its msgid, and save as UTF-8.
    • Keep the placeholders as they are: {}, {0}, {n} (a number) and {{ }}. You can move them within the sentence.
    • Keep config keywords, file names and app names in English (shell.nss, shell.exe, Explorer, Windows Terminal).
    • Text you leave empty, or mark as Needs work in Poedit (#, fuzzy in the file), shows in English.
    • The entry with the context UI font family is not text: it is the font the app uses for your language. Leave it empty unless your script needs a different font.
  3. Test it. In Preferences → Language, click Test a translation file… and choose your file. The whole app switches to your text right away, and a bar at the top says which file is shown and how many of the app's strings it translates, how many are missing, and how many are marked fuzzy. Keep the app open while you work: save the file in your editor, then press Reload in the bar to see the change. Stop goes back to your usual language. Nothing is saved; closing the app ends the test too. You can also start the app with NilesoftShellPro.exe --po "C:\path\to\fr.po".
  4. Share it. Post the file in GitHub Discussions, or, if you know GitHub, open a pull request that puts it at src/settings/translations/<language>/LC_MESSAGES/nilesoft-shell-pro.po. The next version of the app then includes it. A language appears in the Language list once at least half of the app is translated.

When the app gets new text, its .po files get the new entries with an empty translation, and the translations you made are kept. To fix one translation in a language that is already in the app, edit its msgstr in the same way. For developers, Translations in src/settings/README.md explains how the files are built into the app.

Startup and tray

The app can keep running in the system tray, the area next to the clock on the taskbar, so it opens at once and can tell you when a new version is out. Its icon is the Nilesoft Shell Pro logo. If you don't see it, click the small arrow next to the clock: Windows hides some tray icons there.

  • Keep Nilesoft Shell Pro in the system tray (on by default): closing the window leaves the app running in the tray. Click the icon to open the window again. Turn this off and the app works as before: closing the window ends it, and there is no tray icon.
  • Start with Windows (on by default): when you sign in to Windows, the app starts in the tray without opening its window. It only works while the first setting is on, so the switch is greyed out when the app isn't kept in the tray. It only applies to your Windows account, and it doesn't need administrator rights.

Right-click the tray icon for a menu:

  • Open Nilesoft Shell Pro opens the window (clicking the icon does the same).
  • Check for updates checks right away and tells you the result in a notification.
  • Restart Explorer is the same as the button on Home.
  • Quit ends the app until you start it again (or until you next sign in, if Start with Windows is on).

While the app is in the tray it checks for updates a minute or two after Windows starts and then about every eight hours, if Check for updates automatically is on. When it finds a new version you get a Windows notification, Nilesoft Shell Pro 2.x is available. Click to see what's new. Clicking it opens the app on Home, where the update banner is. You are told once about each version, and never about a version you skipped. If Download and install updates automatically is on, the update is also downloaded in the background, as before.

The app runs only once. Starting it from the Start menu while it is in the tray opens the window you already have. In the tray it uses very little: it draws nothing while the window is closed, and it wakes up only for its icon and the update checks.

How Windows starts it: an entry named NilesoftShellPro under HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run, which runs NilesoftShellPro.exe --background. The app adds it the first time you run version 2.2.0 or later, and never again on its own, so if you remove it another way it stays removed. Turning off either setting removes it. It also shows in Settings → Apps → Startup and in Task Manager, where you can turn it off too; the card then says so, and turning Start with Windows on in the app turns it back on there. Uninstalling the MSI closes the app and removes the entry. For a portable copy, turn off Keep Nilesoft Shell Pro in the system tray before you delete the folder. The settings are stored as KeepInTray and StartWithWindows under HKEY_CURRENT_USER\Software\Nilesoft\Shell\Settings.

All users on this PC

This card shows whether Shell is registered for All users and for Just you, and has the one button in the app that needs administrator rights.

  1. Press Register for all users (or Unregister for all users). The UAC shield on the button means Windows will ask.
  2. Choose Yes in the Windows prompt. The app runs shell -register (or -unregister) as administrator.
  3. Restart Explorer from Home so the change takes effect.

On Windows 11, registering for all users also turns on the classic menu unless you turned that off in the first-time setup. If you cancel the prompt, nothing is changed. The MSI already registers Shell for all users; you need this button mainly for a portable copy you want everyone to use. To turn Shell on for your account only, without administrator rights, use Register for me on Home.

Updates

The app looks for new versions in this project's GitHub releases. When one is available, Home shows a banner with Release notes, Download and install and Skip this version, and the sidebar shows Update available above the status line. The Updates card in Preferences has the version you run (and whether it is the MSI, installed for all users, or a portable copy), the channel, the last check and a Check now button.

Updates don't ask for administrator rights. Most updates only change the app and the menu files that come with it, and those are installed for you alone, even when Shell is installed for all users. Only an update that also changes the Shell core (shell.dll and shell.exe, which an all-users install shares with everyone on the PC) needs administrator approval. The banner then says so and offers Install with administrator approval and Later; nothing asks for approval unless you press that button.

Update settings
  • Check for updates automatically (on by default): when the app starts, at most once a day, and once a day while it stays open; about every eight hours while it is in the system tray. A failed automatic check (offline, or GitHub's request limit) stays quiet and is tried again later; Check now says what went wrong.
  • Download and install updates automatically (off by default): the update is downloaded and verified in the background. An app update for an all-users install is also installed for you right away and is used the next time the app starts (or press Restart now); a portable copy is replaced when you press Restart to update. An update that changes the Shell core for all users is never installed automatically: it is only announced, because it needs administrator approval.
  • Channel: Stable offers releases only; Beta also offers pre-releases such as 2.1.0-beta.1. A pre-release build starts on Beta, every other build on Stable.
  • Skip this version (on the Home banner) hides that version; a newer one still shows up.
Installing an update
  1. Save or discard your unsaved changes, on every page. The app closes to install the update, and it won't start the update while Appearance, Behavior or Rules & Filters have changes waiting.
  2. Press Download and install on the Home banner or in Preferences (or Check now first). A progress bar shows the download; Cancel stops it.
  3. When the download is checked, the update is installed:
    • App update (the usual case for an all-users install): installed for you, with no administrator rights and no prompt. Press Restart now to use it right away, or keep working: the next time the app starts, it is the new version.
    • Portable: no administrator rights and no prompt. The app closes for a moment and the files in its folder are replaced.
    • Shell core update for an all-users install (the button has the UAC shield and says Install with administrator approval): the app closes and Windows asks for administrator approval once. Choose Yes. The installer runs with a small progress window and restarts Explorer. Choose Later on the banner if you don't want that now; the update stays in Preferences.
  4. The app opens again on its own and Home says Updated to and the new version. For a portable copy, press Restart Explorer on that banner to load the new shell.dll; until then Explorer keeps using the old one.

After an app update for an all-users install, Home shows two versions next to Version: the Shell core installed for everyone and the newer app you run (for example Shell core 2.1.1 · app 2.2.0). That is expected: the core is updated only when a release changes it.

A file of your configuration in %APPDATA%\Nilesoft\Shell that you edited is never replaced by an update; see Updates and your configuration.

What happens behind the scenes
  1. For an all-users install (the app runs from Program Files and Shell is registered for all users from there), the app first reads the release's update.json. It says which release the Shell core of the new version comes from. When your installed core is at least that release, the app downloads only NilesoftShellPro-<version>-x64-app.zip (the app and the menu files that come with it). Otherwise (or for an older release without update.json) it offers setup-x64.msi or setup-arm64.msi, which needs administrator approval. A portable copy downloads the x64 portable zip. Downloads go to %LOCALAPPDATA%\Nilesoft\Shell\updates\<version>. Only addresses under this project's releases (and the GitHub hosts they redirect to) are accepted.
  2. It is checked against the release's SHA256SUMS.txt, which is downloaded first. A file that doesn't match is deleted and nothing is installed. A release without SHA256SUMS.txt isn't installed at all.
  3. App update: every file in the zip is checked once more against the SHA-256 listed in update.json, then the files are copied to %LOCALAPPDATA%\Programs\Nilesoft Shell Pro\app\<version> with an install.json that lists them. Program Files is not touched. When the app in Program Files starts (from the Start menu or with Windows), it looks there and starts the newest copy that is newer than itself and whose NilesoftShellPro.exe still matches, with the same command line. If that copy is damaged or closes before its window appears, it is removed and the installed app runs instead. Copies older than the installed version (for example after you install a newer MSI) are removed, and so are older copies once a newer one runs. When the app is started as administrator, it never starts a per-user copy.
  4. Your personal configuration is brought up to date from the new version's menu files (see Updates and your configuration), also without administrator rights. A configuration that is still the shared one in Program Files keeps the installed menu files until the next Shell core update, or until you create a personal configuration on Home.
  5. For a portable copy or a Shell core update, the app closes and a copy of it in %TEMP% finishes the job:
    • MSI: Windows asks for administrator approval, then msiexec /i setup-x64.msi /passive /norestart runs (its log is saved next to the MSI). The installer restarts Explorer, and the app opens again on its own.
    • Portable: no administrator rights. The files are copied over the install folder; the shell.dll Explorer has loaded is renamed aside first (Windows allows that for a DLL in use) and removed on a later start. A .nss file you edited in that folder is kept, with the new default saved next to it as .nss.new. If a file can't be replaced, everything is put back. The app opens again and offers Restart Explorer to load the new shell.dll.

Downloads of versions you already have are removed the next time the app starts. The update settings are stored under HKEY_CURRENT_USER\Software\Nilesoft\Shell\Settings.

Troubleshooting updates
You seem to be offline, so updates couldn't be checked.Check your internet connection, then press Check now.
GitHub's limit for update checks was reached.GitHub limits how often one address can ask. Wait an hour and press Check now again.
Save or discard your changes firstAppearance, Behavior or Rules & Filters has unsaved changes. Save them (Ctrl+S) or discard them, then press Download and install again.
The administrator prompt was cancelled. Nothing was changed.Press Restart to update and choose Yes in the Windows prompt. The download is kept, so it isn't downloaded again.
The download doesn't match SHA256SUMS.txtThe file was damaged on the way and has been deleted. Try again; if it keeps happening, download the release from GitHub yourself.
This release has no download for this kind of install.Get the update from the release page (Release notes opens it).
The update wasn't installed (after the app reopens)The message says why. For an MSI, it names the installer's log file next to the MSI. Another installation is in progress means Windows is installing something else: wait and try again.
The update was cancelledThe installer was cancelled; nothing was changed.
Version 2.2.0 couldn't start, so 2.1.1 is running.The app update was installed but closed before its window appeared, so the installed app started instead and the damaged copy was removed. Press Check now to install it again. If it keeps happening, report it and install the MSI from the release page.
The app asks for administrator approval to updateOnly an update that changes the Shell core of an all-users install does, and only after you press Install with administrator approval. Choose Later to keep the version you have.
The update can't be installed from the app at allDownload the MSI or the portable zip from the latest release and install it by hand (see Installation).
About

The About card shows the app's version (and the version of shell.exe if it differs), the licence, links to nilesoft.org, the documentation, this fork's source code and its issue tracker (Report an issue), and the third-party software the app uses: Slint, JSON for Modern C++ and Fluent UI System Icons.
