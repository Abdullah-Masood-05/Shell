Settings



Settings are containers for storing default values.

settings
{
	// Delay before a submenu opens on hover, 0 to 4000 ms.
	// This writes the Windows per-user setting SPI_SETMENUSHOWDELAY while a
	// menu is open, so it overrides whatever the user chose system-wide.
	// The shipped shell.nss sets 200; remove the line to respect their setting.
	showdelay = 200

	// Prevent interaction with these windows or processes
	exclude
	{
		where = boolean value
		window = window name
		process = process name
	}

	// Off unless set: give Shell's menu the selected files in other file
	// managers, such as Total Commander (see "Other file managers" below)
	filemanagers = ['totalcmd64', 'xyplorer']

	// Off unless set: load Windows' own menu handlers when Explorer starts,
	// and keep them loaded between menus, so a right-click does not wait for
	// them (see "Faster menus" below)
	preload = true
	keepalive = true
	// The file types whose menus preload also builds; unset, these
	preload.types = ['jpg', 'png', 'pdf', 'docx', 'mp4', 'mkv', 'html', 'obj']

	tip = true
	// or
	tip
	{
		enabled = true

		// normal = [background, text]
		normal = [default, default]

		// normal = [background, text]
		primary = [#000, #fff]

		// info = [background, text]
		info = [#88f, #fff]

		// success = [background, text]
		success = [#8f8, #fff]

		// warning = [background, text]
		warning = [#ff8, #fff]

		// danger = [background, text]
		danger = [#f88, #fff]

		// max width value from 200 to 2000
		width = 400

		// opacity value from 0 to 100
		opacity = 100

		// radius size value from 0 to 3
		radius = 1

		time = 1.5

		padding = [8, 4]
	}

	// Disable/Enable modify items processing
	modify
	{
		enabled = boolean value
		image = [0 = disable, 1 = enable, 2 = auto reimage]

		// Allow/disallow modification of title
		title = boolean value

		// Allow/disallow modification of visibility
		visibility = boolean value

		// Allow/disallow modification of parent
		parent = boolean value

		// Allow/disallow modification of position
		position = boolean value

		// Allow/disallow to add separator
		separator = boolean value

		// auto set image and group
		auto = boolean value
	}

	// Disable/Enable new items processing
	new
	{
		enabled = boolean value
		// disable/enable image
		image = boolean value
	}
}
The taskbar

When exclude is true on the taskbar, Shell leaves the taskbar's right-click alone and you get Windows' own taskbar menu. On Windows 11 that is the menu with Task Manager and Taskbar settings. On the taskbar window.is_taskbar is true. For example, to keep Shell's menu in File Explorer and on the desktop and give the taskbar back to Windows:

settings
{
	exclude.where = !process.is_explorer or window.is_taskbar
}
Other file managers

In File Explorer, Shell's menu knows which files you right-clicked. Other file managers, such as Total Commander, XYplorer, Double Commander and Everything, build the Windows file menu their own way, and by default Shell's menu there doesn't know the files, so items with type= or sel don't show or don't work.

filemanagers turns this on. It is off unless you set it. Give it the names of the programs, without .exe (what process.name gives), or true for every program but File Explorer. Shell's menu must also be allowed in those programs: the shipped shell.nss leaves out every program but File Explorer with exclude.where = !process.is_explorer, so change that line too:

settings
{
	filemanagers = ['totalcmd64', 'xyplorer', 'doublecmd', 'everything']
	exclude.where = !process.is_explorer && process.name != 'totalcmd64' && process.name != 'xyplorer' &&
		process.name != 'doublecmd' && process.name != 'everything'
}

This is new and has had little testing with these programs. If one of them misbehaves, take it off the list. A right-click on empty space in such a program still has no files.

Faster menus: preload and keepalive

Most of the time between a right-click and the menu is Windows building its own menu: every program that adds items to it (7-Zip, WinMerge, Windows Terminal and so on) is loaded and asked for its items before Shell gets the menu. Three things make that slow. The first right-click after File Explorer starts loads all of them. Some of them run in a process of their own (Windows Terminal's Open in Terminal, for example), which Windows closes shortly after the menu closes, so the next right-click waits for it to start again. And for each of those, every menu asks a Windows service to find the running program again, which gets slower the longer File Explorer runs: in a File Explorer that had been running for a day it took about 135 ms of every right-click. A menu that Windows builds in 30 to 50 ms the second time took 270 to 470 ms in the first two cases when measured.

preload = true builds Windows' menus for a file, a folder, a folder's empty space and the desktop in the background a few seconds after File Explorer starts, without showing them, so the first right-click finds everything loaded. keepalive = true keeps what a menu loaded: the programs' DLLs stay loaded, the ones that run in a process of their own keep running, using a few MB of memory each, and Shell creates those straight from the running program from then on instead of asking the service again. Both are off unless you set them, here or with their switches on the app's Behavior page. preload runs when File Explorer starts; keepalive applies from the next menu after the config is loaded, and once it is turned off, the next menu lets go of what it kept, so Windows unloads the DLLs and closes the programs as it does without it. Items you hide with remove(clsid=...) are never loaded at all.

Some programs add items only for certain file types, such as photo viewers for pictures or Office for its documents, so a file of that type is the only thing that loads them. preload.types lists the types whose menus the preload builds too, from an empty file of each one that it keeps in a folder of your temp folder. Each is an extension, with or without its dot, in a list (['jpg', 'pdf']) or in one string ('jpg|pdf'). Unset, it is ['jpg', 'png', 'pdf', 'docx', 'mp4', 'mkv', 'html', 'obj']; preload.types = '' builds none of them. Each type adds a little to the preload's time, which shell.log shows along with the types it built.

A program whose menu crashes File Explorer during the preload would crash it again at every start, because Windows restarts File Explorer after a crash. So the preload leaves a mark in the registry while it runs, under HKEY_CURRENT_USER\Software\Nilesoft\Shell\Preload, and removes it when it is done. If File Explorer closed before that, later starts skip the preload, and say so in shell.log, until the configuration changes: any change to its files, such as turning preload off and on again, lets it run again.

settings
{
	preload = true
	keepalive = true
	preload.types = ['jpg', 'png', 'pdf', 'docx', 'mp4', 'mkv', 'html', 'obj']
}
